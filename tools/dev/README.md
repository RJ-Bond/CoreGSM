# Локальный стенд для разработки

Панель с демо-данными, где каждое изменение кода видно сразу. Два способа, оба берут код прямо из папки `src/` репозитория.

## Способ 1: без Docker (быстрее, проще)

```
node tools/dev/local.mjs
```

Запускает бэкенд и фронтенд на вашем компьютере прямо из папок панели. Docker не нужен.
Нужны Node 22+ и установленные пакеты (один раз): `cd src/core-backend && npm ci`, `cd src/core-frontend && npm ci`.
На Windows с Node 24 пакет `better-sqlite3` может не собраться: тогда `npm i --no-save better-sqlite3@12` в `src/core-backend` (файл `package-lock.json` не менять).

- Панель: http://localhost:5173, вход `admin` / `Passw0rd!long`
- Бэкенд: http://localhost:3000
- Данные лежат в `tools/dev/.data` (в репозиторий не попадают), демо-данные кладутся при первом запуске
- Остановка: `Ctrl+C`; с чистыми данными: `node tools/dev/local.mjs reset`
- Порты заняты (например, стендом Docker): `PORT_API=3100 PORT_WEB=5273 node tools/dev/local.mjs`

## Способ 2: в Docker

```
node tools/dev/dev.mjs
```

То же самое внутри контейнеров (Linux, как на сервере). Команда сама запустит Docker Desktop. Первый запуск несколько минут:
пакеты ставятся внутри контейнера. Команды: `down` (остановить), `reset` (стереть данные), `seed`, `logs`, `status`.

## Как видны изменения (оба способа)

| Что меняете | Что происходит |
|---|---|
| `src/core-frontend/**` (компоненты, стили) | страница в браузере обновляется сама (vite) |
| `src/core-backend/src/**` | бэкенд перезапускается сам через секунду-две |

## Что внутри демо-данных

8 серверов разных игр (один офлайн, один с очень длинным названием), ники игроков, история за сутки, три новости, администратор.
Адреса серверов выдуманные, поэтому опрос почти выключен (`POLL_INTERVAL_SEC=86400`): иначе серверы стали бы офлайн.
История считается от момента первого запуска; через сутки графики «сдвинутся», тогда выполните `reset`.

## Если что-то не так

- **«Пакеты не установлены».** Выполните `npm ci` в `src/core-backend` и `src/core-frontend`.
- **Порт занят.** Остановите то, что его использует, или задайте другие порты (см. выше). Не запускайте оба способа одновременно на одних портах.
- **Docker не отвечает** (способ 2). Запустите Docker Desktop и дождитесь «Engine running».
- **Изменения не видны.** Ошибка компиляции видна в окне браузера и в консоли, где запущена команда.
