# Модель данных

База одна: SQLite (режим WAL), файл `coregsm.db` в каталоге данных. Схему создаёт `db.ts` (базовая часть, идемпотентно) и пронумерованные миграции
в `migrations.ts` (только растут). Ниже основные таблицы по смыслу. Список неполный: модули новостей, опросов и сообщества создают свои
таблицы рядом со своим кодом (`grep -rn "CREATE TABLE" src/core-backend/src`).

## Серверы и опрос

| Таблица | Что хранит | Как долго |
|---|---|---|
| `servers` | добавленные серверы: игра, адрес, порт, порт запроса, название, страна | пока не удалён |
| `status` | последнее состояние каждого сервера (онлайн, игроки, пинг, карта, версия, ошибка, счётчик неудач подряд) | одна строка на сервер |
| `history` | точка на каждый опрос: время, игроки, пинг, онлайн, пометки «неподтверждено» и «обслуживание» | `HISTORY_DAYS`, по умолчанию 30 дней |
| `uptime_daily` | сводка по дню: сколько опросов, сколько успешных | `UPTIME_DAYS`, по умолчанию 90 дней |
| `player_now` | кто сейчас в игре и с какого времени | только текущее |
| `player_sessions` | когда игрок зашёл и вышел | `PLAYER_SESSIONS_DAYS`, по умолчанию 90 дней |
| `maintenance_windows` | окна обслуживания (разовые и повторяющиеся) | пока не удалены |
| `health_samples` | здоровье самой панели (размер базы, память) для графика | короткое время |

## Люди и вход

| Таблица | Что хранит |
|---|---|
| `users` | аккаунты: имя, роль, хеш пароля, почта, привязка Discord, статус |
| `sessions` | входы с устройств (идентификатор, время, адрес, браузер); живут 7 дней, старше 8 дней удаляются |
| `user_prefs` | язык, часовой пояс, форматы времени и даты |
| `user_player` | игровой профиль: ник, описание, публичность |
| `favorites`, `favorite_push_prefs` | избранные серверы и правила push по ним |
| `account_events` | журнал входов и действий аккаунта (`ACCOUNT_EVENTS_DAYS`, по умолчанию 180 дней) |
| `api_keys` | ключи публичного API: хеш, префикс, лимит, список адресов, срок |
| `login_guard` | блокировки после неверных паролей |

## Оповещения и Discord

| Таблица | Что хранит |
|---|---|
| `bindings` | какое сообщение со статусом в каком канале Discord к какому серверу привязано |
| `alert_channels` | дополнительные каналы: вебхуки и почта, с подписью и повторами |
| `smart_state` | состояние «умных» оповещений (мало игроков, вырос пинг, почти заполнен) |

## Игровой плагин

`game_news_*` (цели, шаблоны, правила, журнал сообщений), `game_commands`, `game_identities` (связь аккаунта с игровым идентификатором),
`game_bans`, `game_mod_log` (модерация), `game_restart_*` (рестарты игры по расписанию и задачам).

## Служебное

| Таблица | Что хранит |
|---|---|
| `settings` | настройки сообщества «ключ — значение»; секреты зашифрованы |
| `settings_history` | кто, что и из чего во что менял в настройках, которые задаёт человек (без секретов); последние 2000 записей |
| `audit` | журнал действий администраторов (последние 2000 записей) |
| `rum_samples` | числа скорости страниц у посетителей (LCP, INP, CLS, TTFB, FCP) без данных о человеке; хранятся 14 дней |
| `schema_migrations` | какие миграции применены |

## Правила работы со схемой

- Миграции только добавляются в конец, каждая в своей транзакции и идемпотентна; выпущенные не правятся.
- Перед применением к существующей базе делается копия `backups/pre-migrate-v<N>-<время>.db` (хранятся пять последних).
- Секреты никогда не пишутся в открытом виде; ключ `SECRETS_KEY` хранится в `.env`, а не в базе.
- Изменение настройки из списка `admin/portableSettings.ts` автоматически попадает в `settings_history`; новые настройки, которые задаёт человек, добавляйте в этот список:
  он же определяет, что переносит файл «Экспорт настроек».
