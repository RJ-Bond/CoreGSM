# Как устроен CoreGSM

Коротко о том, из чего состоит панель, как данные идут от игрового сервера до экрана и где что лежать в коде. Для тех, кто хочет
разобраться или помочь с разработкой. Что проверяет CI и как запускать, написано в [CONTRIBUTING.md](../CONTRIBUTING.md).

## Части

```
 игровой сервер ◄── опрос ──┐
 (Steam/UDP/RCON …)         │
                            ▼
 браузер ◄─ nginx ─► backend (Express 5, SQLite) ◄─ внутренний токен ─► bot (discord.js)
              │            ▲   ▲
              │            │   └─ плагин игры (BepInEx): чат, модерация, рестарты
              └─ статика   └─ точки проверки (probe) на другой машине
                 панели
```

| Часть | Где | Что делает |
|---|---|---|
| **backend** | `src/core-backend` | Опрашивает серверы, хранит историю, отдаёт API панели и публичное API, рисует картинки (карточки, превью), рассылает оповещения, делает копии |
| **frontend** | `src/core-frontend` | Панель на React 19 и Vite, Tailwind v4 и свои таблицы стилей. Два вида: классика и Ember (атрибут `data-ember` на `<html>`) |
| **bot** | `src/core-bot` | Discord-бот: сообщения со статусом, команды, роли, модерация. Берёт задачи у backend по внутреннему токену |
| **nginx** | `src/nginx` | TLS, ограничения частоты, статика панели, прокси `/api` на backend |
| **установщик** | `install.sh`, `tools/` | `install.sh` собирается из исходников командой `bash tools/build-installer.sh`; ставит и обновляет панель через Docker Compose |

Все данные лежат в одной базе SQLite (режим WAL) и в нескольких файлах рядом (копии, логотип, обложки). Бот и backend — отдельные контейнеры;
база принадлежит только backend.

## Путь данных: от опроса до экрана

1. **Опрос.** Таймер (`POLL_INTERVAL_SEC`, по умолчанию 30 с) запускает `pollAll` (`monitoring/gsm.ts`). Серверы опрашиваются пулом из
   `POLL_CONCURRENCY` (по умолчанию 8, от 1 до 32) через gamedig и собственные запросы к играм (`monitoring/query.ts`).
2. **Решение.** `applyPollResult` пишет состояние в `status`, точку в `history`, игроков в `player_now` и `player_sessions`. Сбой не объявляется
   сразу: правило «N из M», проверка с точек `probe` и окна обслуживания (`alerts/downVerdict.ts`) решают, считать ли сервер упавшим.
3. **Шина событий.** После опроса в `events.ts` уходят события `server.polled` и (при смене состояния) `server.state`. Слушатель не знает, кто ещё слушает,
   и не может сломать остальных.
4. **Живые обновления.** `live.ts` слушает шину и по одному длинному соединению (`GET /api/live`, Server-Sent Events) говорит открытым панелям
   «список устарел». Данные по этому соединению не идут: панель сама перезагружает список, поэтому права доступа решает обычный `/api/servers`.
5. **Оповещения.** Падение и возврат попадают в очередь доставок (`alerts/deliveries.ts`). Её разбирают бот (Discord), почта, push и
   исходящие вебхуки с подписью HMAC (`alerts/alertChannels*.ts`). Каждая доставка повторяется с задержкой и видна в журнале доставок.
6. **Панель.** Фронтенд опрашивает API раз в 10 секунд (раз в минуту, пока открыто соединение живых обновлений) и рисует состояние.

## Карта кода backend (`src/core-backend/src`)

| Папка | Что внутри |
|---|---|
| `monitoring/` | опрос серверов, игры, история, метрики Prometheus, здоровье панели, точки проверки, плановые рестарты и вайпы, скорость у посетителей (`rum.ts`) |
| `alerts/` | оповещения, каналы (вебхук, почта, push), итоги недели, очередь личных сообщений, выбор канала для служебных сообщений |
| `admin/` | настройки сообщества и оформления, резервные копии, журнал и история настроек, обновление панели, публичное API v1, OpenAPI |
| `security/` | вход, сессии, 2FA, подтверждение пароля (step-up), ключи API, капча на доказательстве работы, ограничения частоты |
| `news/`, `community/`, `profile/` | новости, опросы, сообщество, рейтинги, профили игроков |
| `gamenews/` | сообщения в игру, модерация, рестарты игры через плагин |
| `discord/` | настройки и вход через Discord, связь с ботом |
| `images/` | карточки, превью, итоги недели, обложки (skia-canvas) |
| `routes/` | остальные маршруты API панели |

Основные файлы: `index.ts` (сборка приложения и таймеры), `db.ts` (SQLite и настройки), `migrations.ts` (миграции схемы), `schema.ts`,
`events.ts` (шина), `actor.ts` (кто делает запрос), `shutdown.ts` (аккуратная остановка), `errors.ts` (каталог текстов ошибок).

## Как устроены настройки

Настройки сообщества лежат в таблице `settings` (ключ и значение). Секреты (токен бота, пароль почты) хранятся зашифрованными ключом `SECRETS_KEY`
(`security/secrets.ts`). Каждое изменение настройки из списка `admin/portableSettings.ts` попадает в `settings_history`: кто, что, из чего в что;
из панели его можно вернуть. Секреты в историю не пишутся.

## Миграции и безопасность обновления

Схема живёт в `migrations.ts`: список пронумерованных миграций только растёт, выпущенные не правятся. Перед применением новых миграций к
существующей базе рядом кладётся согласованная копия (`backups/pre-migrate-v<N>-<время>.db`, хранятся пять последних). Ошибка миграции останавливает запуск
с понятным сообщением: копия и есть путь назад (см. [operations.md](operations.md)).

## Фронтенд

- Страницы в `src/pages`, повторно используемые части в `src/components` и `src/ui`, стили в `src/index.css` и `src/styles/*.css`.
- Текст интерфейса только через `t('ключ')`; ключи в `locales/ru.ts` и `locales/en.ts` одновременно (проверяет тест).
- Вид Ember: токены и правила в `styles/ember.css`, включается атрибутом `data-ember`; цвет Ember на выбор через `data-ember-accent`.
- Тяжёлые страницы подгружаются по требованию (`lazyPage`); бюджет веса первого захода проверяет CI (`scripts/bundle-budget.mjs`).
- Быстродействие у настоящих посетителей собирает `rum.ts` (числа без данных о человеке), итоги видны в админке на странице «Система».

## Безопасность в двух словах

Сессия в HttpOnly-куке плюс защита от CSRF по заголовку `X-CoreGSM`; 2FA и подтверждение пароля для опасных действий; ключи API с
ограничением частоты и списком адресов; ограничения частоты в nginx и в backend; контейнеры с `read_only`, без привилегий и с лимитами памяти;
цепочка поставок (подписи релиза, SBOM, CodeQL, поиск секретов). Подробнее в [SECURITY.md](../SECURITY.md).
