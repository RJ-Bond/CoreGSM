# CoreGSM

Self-hosted аналог DiscordGSM. Веб-панель, где вы добавляете игровые серверы, и Discord-бот, который публикует в канале красивую картинку со статусом сервера и сам обновляет её по таймеру.

![Пример карточки](docs/card-preview.png)

- **Панель**: React и Tailwind, светлый дизайн Pastel Soft. Серверы, карточки, привязка каналов, смена пароля.
- **Бэкенд**: Node.js 20, TypeScript, Express, [GameDig](https://github.com/gamedig/node-gamedig) (опрос серверов), SQLite, генерация PNG-карточек.
- **Бот**: discord.js 14. Отправляет одно сообщение с картинкой в канал и дальше редактирует его.
- **Nginx**: HTTPS, редирект с HTTP, Let's Encrypt с автопродлением.
- **Прокси**: SOCKS5 и HTTP для бота и установки (см. раздел «Прокси»).

Всё ставится одной командой: один скрипт `install.sh` сам создаёт файлы проекта, ставит Docker и запускает контейнеры.

## 1. Что понадобится

| Что | Зачем |
| --- | --- |
| Сервер с чистым **Debian 13** (подойдёт и 12), доступ по SSH, права root | Здесь будет работать панель |
| 2 ГБ ОЗУ и 5 ГБ диска | Сборка Docker-образов |
| Токен Discord-бота | Чтобы бот мог публиковать карточки. Можно добавить позже (см. [раздел 5](#5-создание-discord-бота)) |
| **Для боевого режима:** домен с A-записью на IP сервера и e-mail | Для HTTPS-сертификата Let's Encrypt |
| **Для локального режима:** ничего, достаточно IP-адреса | Сертификат создаётся самоподписанный |

## 2. Установка на сервер в локальной сети (по IP)

Этот режим для разработки и домашнего сервера. Пример для адреса `192.168.88.152`. Публичный домен не нужен: Let's Encrypt не выдаёт сертификаты на IP и внутренние имена, поэтому установщик сам создаёт самоподписанный сертификат и пропускает Certbot.

**Шаг 1.** Скопируйте `install.sh` на сервер (подробнее в [разделе 4](#4-как-доставить-installsh-на-сервер)). С компьютера на Windows, в PowerShell:

```powershell
scp D:\CoreGSM\install.sh root@192.168.88.152:/root/
```

**Шаг 2.** Подключитесь к серверу и запустите установщик:

```bash
ssh root@192.168.88.152
bash install.sh
```

Если вы вошли не под root, используйте `sudo bash install.sh`. На минимальном Debian `sudo` может отсутствовать: выполните `su -` и запускайте от root.

**Шаг 3.** Ответьте на вопросы:

| Вопрос | Что ввести |
| --- | --- |
| Прокси | Просто Enter, если прокси не нужен (см. [раздел 7](#7-прокси)) |
| Токен Discord-бота | Вставьте токен или нажмите Enter, чтобы добавить позже |
| Домен или IP | `192.168.88.152` |

Вопроса про e-mail не будет: в локальном режиме он не нужен.

**Шаг 4.** Подождите 5-10 минут: установщик обновит систему, поставит Docker, соберёт образы и запустит контейнеры. В конце он покажет итог:

```
  Панель:   https://192.168.88.152
  Логин:    admin
  Пароль:   ********************
```

**Сохраните пароль.** Он также записан в `/app/.env`. Потом его можно сменить в панели («Настройки»).

**Шаг 5.** Откройте `https://192.168.88.152` в браузере. Появится предупреждение о сертификате: это нормально для самоподписанного сертификата. Нажмите «Дополнительно», затем «Перейти на 192.168.88.152». Войдите как `admin`.

Без вопросов, одной командой:

```bash
DISCORD_TOKEN='ваш_токен' DOMAIN=192.168.88.152 SKIP_UPDATE=1 bash install.sh
```

## 3. Установка на сервер с доменом (боевой режим)

Перед запуском проверьте две вещи:

1. У домена (например, `gsm.my-domain.com`) есть A-запись на публичный IP сервера.
2. Порты 80 и 443 сервера доступны из интернета (на роутере проброшены, у хостера не закрыты).

Затем:

```bash
bash install.sh
```

Установщик спросит токен бота, домен и e-mail для Let's Encrypt, выпустит настоящий сертификат и включит автопродление. Итог такой же, как выше, только адрес панели будет `https://gsm.my-domain.com`.

Если сертификат получить не удалось (DNS ещё не обновился или закрыт порт 80), установщик создаст временный самоподписанный, и панель всё равно запустится. Исправьте причину и запустите `bash install.sh` ещё раз: пароль и секреты сохранятся, а сертификат будет выпущен заново.

Без вопросов:

```bash
DISCORD_TOKEN='ваш_токен' DOMAIN=gsm.my-domain.com LE_EMAIL=me@example.com bash install.sh
```

## 4. Как доставить install.sh на сервер

Репозиторий приватный, поэтому на сервере простой `git clone` без авторизации не сработает. Выберите любой способ.

**Способ A (проще всего): скопировать один файл.** `install.sh` полностью самодостаточен, в нём уже лежит весь код проекта.

```powershell
scp D:\CoreGSM\install.sh root@192.168.88.152:/root/
```

`scp` встроен в Windows 10 и 11. Если пользователь на сервере не root, замените `root` на его имя и положите файл в домашнюю папку.

**Способ B: клонировать репозиторий с токеном GitHub.** Создайте на GitHub токен (Settings → Developer settings → Personal access tokens → Fine-grained, доступ только на чтение к репозиторию CoreGSM), затем на сервере:

```bash
apt-get update && apt-get install -y git
git clone https://RJ-Bond:ВАШ_ТОКЕН@github.com/RJ-Bond/CoreGSM.git
cd CoreGSM
bash install.sh
```

**Способ C: сделать репозиторий публичным.** Тогда на сервере достаточно `git clone https://github.com/RJ-Bond/CoreGSM.git`.

## 5. Создание Discord-бота

1. Откройте [Discord Developer Portal](https://discord.com/developers/applications), нажмите **New Application**, задайте имя.
2. Слева выберите **Bot**, нажмите **Reset Token** и скопируйте токен. Он показывается один раз. Никому его не передавайте.
3. Приглашение бота на ваш Discord-сервер: в браузере откройте ссылку, подставив вместо `ID_ПРИЛОЖЕНИЯ` значение **Application ID** со страницы General Information:

   ```
   https://discord.com/oauth2/authorize?client_id=ID_ПРИЛОЖЕНИЯ&scope=bot&permissions=52224
   ```

   Права `52224` это: просмотр канала, отправка сообщений, встраивание ссылок, прикрепление файлов. Больше боту ничего не нужно, привилегированные intents включать не надо.
4. Если токен не вводили при установке, добавьте его позже:

   ```bash
   nano /app/.env          # впишите DISCORD_TOKEN=...
   cd /app && docker compose up -d bot
   ```

## 6. Первый вход и настройка

1. Войдите в панель (`admin` и пароль из итога установки).
2. **Серверы** → **Добавить сервер**. Выберите игру, введите адрес и порт игрового сервера. Панель сразу его опросит и покажет онлайн, карту и пинг. Если сервер «DOWN», под названием будет причина.
3. **Discord** → **Привязать канал**:
   - Включите в Discord режим разработчика (Настройки → Расширенные), нажмите на нужный канал правой кнопкой и выберите **Копировать ID канала**.
   - Вставьте ID, выберите сервер и интервал обновления (от 30 секунд).
4. Через несколько секунд бот отправит в канал карточку и дальше будет редактировать это же сообщение. Состояние привязки видно на странице «Discord»: «РАБОТАЕТ» или «ОШИБКА» с причиной.
5. **Карточки**: здесь видно, как выглядят картинки, и можно скопировать ссылку на PNG.

> Сервер, который вы опрашиваете, должен быть доступен **с самой машины, где стоит панель**. Для серверов в той же локальной сети это обычно так.

## 7. Прокси

Нужно, например, если Discord заблокирован у вашего провайдера. Установщик спросит адрес прокси в начале. Форматы:

```
socks5://127.0.0.1:1080
socks5://логин:пароль@host:1080
http://host:3128
http://логин:пароль@host:3128
```

Enter означает «без прокси». Адрес можно передать заранее: `PROXY_URL=socks5://127.0.0.1:1080 bash install.sh`.

| Что | Идёт через прокси |
| --- | --- |
| Бот → Discord | да, SOCKS5 и HTTP |
| apt, curl, загрузка образов Docker при установке | да, SOCKS5 и HTTP |
| Сборка образов (npm) и продление сертификата | только HTTP и HTTPS (npm и certbot не умеют SOCKS) |
| Опрос игровых серверов | нет, всегда напрямую (это UDP и TCP, HTTP-прокси его не пропускает) |
| Бот → бэкенд внутри Docker | нет |

Для SOCKS имена хостов определяются на стороне прокси, поэтому блокировка DNS для Discord не мешает.

Сменить прокси позже: измените `PROXY_URL` (и `BUILD_PROXY`) в `/app/.env`, затем `cd /app && docker compose up -d bot`.

## 8. Обновление и разработка

Исходники лежат в папке `src/`. Файл `install.sh` **генерируется** из них, руками его править не нужно.

Порядок работы при разработке:

1. Измените код в `src/` на своём компьютере.
2. Пересоберите установщик (в Git Bash или WSL):

   ```bash
   bash tools/build-installer.sh
   ```

3. Отправьте на сервер и запустите повторно:

   ```powershell
   scp D:\CoreGSM\install.sh root@192.168.88.152:/root/
   ssh root@192.168.88.152 "SKIP_UPDATE=1 DOMAIN=192.168.88.152 bash install.sh"
   ```

Повторный запуск безопасен: пароль администратора, секреты, база данных и сертификат сохраняются. `SKIP_UPDATE=1` пропускает полное обновление системы, и всё занимает пару минут. Значения токена, домена и прокси при повторном запуске берутся из `/app/.env`, поэтому вопросов не будет.

Запуск частей на своём компьютере без Docker:

```bash
# бэкенд (нужен Node.js 20+ и компилятор для better-sqlite3)
cd src/core-backend && npm install && npm run build
DB_PATH=./data/dev.db JWT_SECRET=dev-secret-dev-secret INTERNAL_TOKEN=dev-token-dev-token ADMIN_PASSWORD=admin12345 npm start

# фронтенд (в другом терминале; /api проксируется на localhost:3000)
cd src/core-frontend && npm install && npm run dev
```

## 9. Управление и обслуживание

Все команды выполняются на сервере в папке `/app`.

| Задача | Команда |
| --- | --- |
| Состояние контейнеров | `docker compose ps` |
| Логи всех сервисов | `docker compose logs -f` |
| Логи бота | `docker compose logs -f bot` |
| Перезапустить всё | `docker compose restart` |
| Применить изменения в `.env` | `docker compose up -d` |
| Остановить | `docker compose down` |
| Запустить снова | `docker compose up -d` |

**Где что лежит**

| Файл | Содержимое |
| --- | --- |
| `/app/.env` | Пароль, секреты, токен бота, домен, прокси. Права 600, никому не показывайте |
| Docker-том `coregsm_coregsm-data` | База данных SQLite (серверы, привязки, история) |
| `/app/certbot/conf` | Сертификаты |

**Резервная копия базы**

```bash
docker run --rm -v coregsm_coregsm-data:/data -v "$PWD":/backup debian:bookworm-slim \
  tar czf /backup/coregsm-data.tgz -C /data .
```

**Забыли пароль администратора.** Задайте новый (вместо `НОВЫЙ_ПАРОЛЬ` вставьте свой, не короче 10 символов):

```bash
cd /app
docker compose exec backend node -e "const db=require('better-sqlite3')('/data/coregsm.db');const b=require('bcryptjs');db.prepare('UPDATE users SET password_hash=? WHERE username=?').run(b.hashSync(process.argv[1],12),'admin');console.log('ok')" НОВЫЙ_ПАРОЛЬ
```

**Полное удаление**

```bash
cd /app && docker compose down -v     # удалит и базу данных
rm -rf /app
```

## 10. Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| Браузер ругается на сертификат | В локальном режиме это нормально (нажмите «Дополнительно» и «Перейти»). В боевом режиме значит, что Let's Encrypt не выдал сертификат: проверьте A-запись и порт 80, запустите `bash install.sh` ещё раз |
| Панель не открывается | `docker compose ps` и `docker compose logs --tail=100`. Проверьте, что в UFW открыты 80 и 443: `ufw status` |
| Сервер в панели «DOWN» | Под названием написана причина. Проверьте игру, адрес и порт. Для некоторых игр нужен отдельный query-порт (поле в форме). Сервер должен быть доступен с машины панели |
| Привязка Discord «ОШИБКА» | Текст ошибки виден на карточке привязки. Частые причины: неверный ID канала, бот не приглашён на сервер, у бота нет прав на канал |
| Привязка «ОЖИДАНИЕ» долго | Не задан токен бота (`DISCORD_TOKEN` в `/app/.env`) или бот не может подключиться к Discord. Смотрите `docker compose logs bot`. Если Discord заблокирован, [настройте прокси](#7-прокси) |
| Ошибка «Слишком много попыток» при входе | Подождите 10 минут: вход ограничен по частоте |
| Установщик остановился на ошибке | Сообщение укажет строку и команду. Исправьте причину и запустите `bash install.sh` ещё раз, это безопасно |

## 11. Как это устроено

```
Браузер ──HTTPS──▶ nginx-proxy ──▶ frontend   (статика React)
                        │
                        └──/api──▶ backend ◀──── bot ──▶ Discord
                                      │
                                   SQLite (том)
                                      │
                              GameDig ──▶ игровые серверы
```

- Наружу открыты только порты 80 и 443 контейнера nginx. Бэкенд, бот и фронтенд доступны лишь внутри сети Docker, поэтому Docker не обходит правила UFW. UFW разрешает только SSH, 80 и 443.
- Вход ограничен по частоте (nginx и приложение), токен входа живёт 7 дней, пароль хранится как bcrypt-хеш.
- Картинка `/api/card/<id>.png` открыта без входа, чтобы Discord мог её загрузить. В ней только публичные данные о статусе сервера.
- Бэкенд опрашивает серверы каждые 30 секунд (`POLL_INTERVAL_SEC` в `.env`) и хранит историю онлайна 7 дней.

Структура репозитория:

```
install.sh                 готовый установщик (генерируется)
src/                       исходники, зеркалируют /app на сервере
  core-backend/            API, опрос серверов, рендер карточек
  core-frontend/           панель управления
  core-bot/                Discord-бот
  nginx/                   реверс-прокси
  docker-compose.yml
tools/
  installer-head.sh        логика установщика
  build-installer.sh       собирает install.sh со всеми файлами внутри
docs/                      макеты дизайна и превью карточки
```
