# Правила работы над CoreGSM

- **Релиз не готовить и не выпускать, пока владелец не скажет** («выпускай»). До этого новые пункты только дописываются в раздел «Не выпущено | Unreleased» файла `CHANGELOG.md`. По команде: раздел переименовывается в `## <версия> · <дата>` (версия — из `version.txt`, отдельным коммитом), после мерджа и зелёного CI на `main` запускается workflow `release`.
- **`CHANGELOG.md` пишется на двух языках**: `эмодзи русский текст | английский текст` (см. правила в самом файле). Каждый PR с видимыми пользователю изменениями добавляет пункты туда.
- Перед каждым коммитом, который меняет `src/**` или `tools/**`: `bash tools/build-installer.sh` (обновляет `install.sh` и `version.txt`, номер версии растёт сам).
- Сообщения владельцу — по-русски. Работаем напрямую в `main` (решение владельца): коммит и `git push origin main` без веток и PR, перед push — `git pull --rebase origin main`. Историю `main` не переписывать без прямой просьбы владельца.
- В коммитах, PR и файлах не указывать Claude и Claude Code как автора или соавтора (без строк `Co-Authored-By`, `Generated with`, `Claude-Session`).
